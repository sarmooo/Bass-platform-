Bass · Enterprise AI Automation Platform

Automations that reason, act, and stay accountable.

Companies describe a process once; Bass runs it on every trigger — AI agents that reason and call tools, sequenced by a deterministic engine, gated by policy and human approval, and recorded as a replayable trace. The core idea: keep orchestration deterministic and confine non-determinism to individual steps.

Lifecycle of a run

Every execution is durable and traced

A run survives process restarts and resumes from its last committed step. Because state is durable and the log append-only, any run can be paused, resumed, replayed, or forked.

Workflow node types

Composition lives in the deterministic engine

Multi-agent patterns — pipeline, router, planner/executor, reviewer — are built from these nodes, so every hand-off is logged, retryable, and budget-bounded.

agent
Runs the LLM loop with a role, tool allow-list, and guardrails.
tool
One typed call to a connector; read-only or mutating.
branch
Evaluates a condition and chooses the next node.
approval
Pauses the run for a human decision, with timeout.
loop / wait
Iterate over items, or wait until a time or event.
sub_workflow
Invoke another workflow as a single step.

The safety gate

Every tool call is a policy decision

Evaluated on tenant, agent, tool, arguments, cost, and data class. Default posture: read-only is allowed, mutating actions are denied unless explicitly permitted or approved.

ALLOW
Action proceeds. Read-only tools take this path by default.
REQUIRE_APPROVAL
Run pauses; a human approves with full context before the action runs.
DENY
Action blocked and escalated. The system fails closed when in doubt.
