# 11 · Supply Chain & Repository Governance

How changes get from a pull request to a signed, deployed release, and the
controls that gate each step. Companion to the [operations runbook](10-operations.md).

---

## The pipeline at a glance

```
PR ──► CI (required checks) ──► merge ──► tag vX.Y.Z ──► Release ──► Deploy (gated)
        unit / integration          CODEOWNERS      build+sign+SBOM   production env
        temporal / docker+scan       review          GitHub Release    (approval)
        deploy-validate
```

Every arrow is a control:

| Stage | Control | Where |
|-------|---------|-------|
| PR | required status checks + code-owner review | branch protection (settings) |
| Image | Trivy scan gates fixable CRITICALs | `ci.yml` docker job |
| Image | SBOM + SLSA provenance + cosign signature | `ci.yml`, `release.yml` |
| Release | semver tag → signed image + GitHub Release notes | `release.yml` |
| Deploy | environment approval + pre-upgrade migration Job | `deploy.yml`, Helm hook |

---

## Continuous integration

Workflows in [`.github/workflows`](../.github/workflows):

- **ci.yml** — `unit` (ruff, mypy, pytest + 80% coverage gate, pip-audit),
  `integration-postgres` (real PostgreSQL + Redis), `temporal`, and `docker`
  (build → Trivy scan → smoke → k6 load-smoke → SBOM/provenance → cosign sign +
  verify → publish).
- **deploy-validate.yml** — `helm lint`/`template`/kubeconform + `docker compose
  config`. Runs on any `deploy/**` change.
- **scorecard.yml** — advisory OpenSSF Scorecard (artifact, non-blocking).

### Required status checks (set in branch protection)

Configure these as **required** on the default branch (Settings → Branches →
Branch protection). They cannot be set from a file:

- `Lint, types & unit tests (SQLite)`
- `Integration tests (real PostgreSQL)`
- `Temporal durable execution`
- `Build, smoke-test, load-test, sign & publish image`
- `Helm lint, template & schema-validate`
- `Validate docker-compose`

Also enable: **Require a pull request before merging**, **Require review from
Code Owners** (`.github/CODEOWNERS`), **Require branches to be up to date**, and
**Require linear history**.

## Releasing

Releases are cut from a semver tag:

```bash
git tag v0.1.0
git push origin v0.1.0
```

`release.yml` then builds and pushes `ghcr.io/sarmooo/bass:v0.1.0` (+ `:latest`)
with an SBOM and SLSA provenance, signs it keyless with cosign, verifies the
signature, and publishes a GitHub Release with autogenerated notes and the image
digest.

### Verify an image before running it

```bash
cosign verify ghcr.io/sarmooo/bass@<digest> \
  --certificate-identity-regexp "https://github.com/sarmooo/Bass-platform-/.*" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"
```

## Deploying

`deploy.yml` runs on a published Release (or manual dispatch) and is gated on the
**`production` GitHub Environment**. Configure in Settings → Environments →
`production`:

- **Required reviewers** — the approval gate before any apply.
- **Secrets** — `KUBE_CONFIG` (base64 kubeconfig). Absent → the job runs a
  client-side `helm --dry-run` instead of applying, so it's safe pre-cluster.
- Optionally restrict deployment branches/tags to `v*`.

The chart runs schema migrations as a **pre-upgrade hook Job**, so a bad
migration blocks the rollout instead of shipping broken code. Rollback is a Helm
revision revert (migrations are expand→migrate→contract, backward-compatible for
one release).

## Dependency & vulnerability management

- **Dependabot** (`.github/dependabot.yml`) — pip + Actions updates.
- **pip-audit** — advisory dependency CVE scan in `unit`.
- **Trivy** — image OS/library scan; gates fixable CRITICALs, reports HIGH.
- **Pin actions by major tag**; consider pinning to commit SHAs to raise the
  Scorecard "Pinned-Dependencies" score.

## What still lives in repo settings (not in files)

These require repo admin and are intentionally **not** committable — apply them
once in the GitHub UI/API:

1. Branch protection with the required checks above.
2. The `production` environment + required reviewers + `KUBE_CONFIG`.
3. (Optional) GitHub Advanced Security for code-scanning SARIF ingestion, if you
   want Trivy/Scorecard results in the Security tab rather than as artifacts.
